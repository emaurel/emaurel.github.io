Agent Environment

Flagship

An agent-operated web agency, built on the Claude Agent SDK and rendered as a pixel-art world you supervise from above. Eleven agents across twelve rooms find local businesses that trade without a website, research them from public sources and their own published photographs, build them a site on spec, check it in a real browser, publish a preview and email the owner a quote.

A human approves at three gates - publish, send, deliver. Everything between them routes itself: when a lead changes stage, the room whose workbench declares that stage is dispatched. Python / FastAPI + WebSockets backend, Vite + TypeScript + Phaser frontend, ~16k lines.

  • Agents that build their own tools. An agent that hits a missing capability files a tool request; an overseer agent reviews it, a toolsmith agent writes the MCP module, it hot-loads, and the interrupted run is retried automatically. Risky requests wait for human approval.
  • The rooms are the routing table. Each room is a YAML manifest declaring which workbench handles which pipeline stage - so adding a stage is a file, not a change to the engine.
  • Agents hire each other. A room staffs up to ten interchangeable workers under load, and an agent mid-task can hire a specialist for one subtask - a logo, an icon set - which can ask another room to review its work before handing back.
  • Nothing judges a page it hasn't seen. An HTTP fetch can't tell a firewall block from a dead site, so the audit returns inconclusive rather than a score, and only a model that has rendered the page in Playwright and looked at the screenshot may judge it.
  • Guardrails live in code, not prompts. Previews ship noindex and an unaffiliated-preview banner, drafts are scanned for billing language, a QA pass without visual proof is downgraded, and a build that produced no files is a failed run whatever the model reported.

Lorekeeper

Flagship

A Flutter e-reader for people who read long series - the part no reader app handles. It opens EPUB, PDF, TXT and Kindle's AZW / AZW3 / MOBI, then adds the layer around the book: a cast of characters with relationships, affiliations and status timelines, saved citations, notes, and passage-level links between books, all on-device.

The idea it's built around is spoiler-aware notes. Every character description is anchored to the plot point it reveals - book, chapter, even the page inside that chapter - so the app hides what you haven't read yet and reveals it as you go. ~24k lines of Dart across 12 feature modules, 22 versioned SQLite migrations, EN / FR / SV.

  • Kindle formats, no desktop step. AZW / AZW3 / MOBI are converted to EPUB on import by kindle_unpack, the sister library I wrote from scratch in pure Dart because the Flutter ecosystem had nothing that could read them.
  • A cast that changes as you read. Characters carry nested affiliations, relationships, a status timeline and a graph view - and every entry knows which plot point it belongs to.
  • Reading measured, not guessed. Page turns are logged as events, which gives day / week / month charts, a word count and an all-time view rather than a self-reported streak.
  • Your library stays yours. Bundles round-trip a book with its characters, customs and relationships; backup and restore survive an app-package rename by rewriting stored absolute paths.
  • Built like a shipped app. Riverpod + go_router, three paginated rendering engines (CSS multi-column WebView, pdfx, a TextPainter paginator), CI that writes real changelogs, and a privacy policy and landing page for the Play Console.

A pure-Dart library that reads Amazon Kindle formats (MOBI / AZW / AZW3 / KF8) and re-emits them as EPUB 3 - filling a real gap in the Flutter ecosystem.
